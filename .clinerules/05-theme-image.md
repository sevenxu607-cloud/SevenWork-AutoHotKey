# 05 · 从图片生成主题（配方 + 偏好）

> **一张图 → 一套能用、好看、文字读得清的主题，一轮到位。**
> 原理与实测账见 [`docs/THEME-IMAGES.md`](../docs/THEME-IMAGES.md)；本文件是**执行清单 + 用户偏好**。

> ⚠ **当前状态**：主题表只留「哑光灰」一套，图主题（星空 / 金克斯）已下线待打磨。
> 本清单不因此失效 —— 要接回图主题时照它出图即可。

## 一、默认偏好（照这个出图，不必再问）

| 项 | 偏好 | 落到参数 |
| --- | --- | --- |
| **主体大小** | **要完整主体，不要大特写** | `-CropW 1.00`（取满原图宽 = 主体原图大小）；**不低于 0.90** |
| **明暗** | **保留原图明暗，亮部要看得到** | `-Knee 138 -HiMax 200`（亮部 p95 压到原图的 ~85%） |
| **饱和** | **一点都不能掉** | 只做 **V 空间等比缩放**；绝不混色 / 混白 |
| **文字可读** | **让位于画面观感**（明确可牺牲） | 不为配深字去提亮暗图；宁可亮部压得轻 |
| **配色** | **从图里长出来** | `pick-theme-colors.ps1` 给基准：`win` = 均色 × 0.55、`text` 近白 / 深、`dim` 同族中间调；再按图的手动微调一档（色相往主色偏、文字带同色相） |
| **备份** | 重烘前备份成品 | `<成品>_bak_<参数摘要>.png`，**只留最近 2 个** |
| **验收** | 必须真机看文字压图 | 重启程序 → 截图（见 04-workflow） |

**一句话：「原图直出 + 只压亮部 + 主体完整」。**

翻过的两次车都是背离它：

- ① 为配深字把暗图整体提亮到均亮 170 → 洗白，饱和 45.8% → 26%
- ② `-CropW 0.72` 裁成大特写 → 脸顶到框，就是「人物太大」那次

## 二、五步

### 1 量图（先决定动不动它）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\pick-theme-colors.ps1 `
    -Image "D:\Pictures\你的图.png" -Name "极光"
```

出均色、luma p10/p50/p90、宽高比修剪提示、亮/暗判据，以及可直接粘贴的 `Themes` 条目。
⚠️ **它不输出网格 p90** —— 要定位「亮块集中在哪几行哪几列」（决定裁哪块、`Knee` 定在哪），
得自己按 12x12 网格再算一遍。
判据（WCAG 4.5:1）：**亮字要背景 ≤ 118；深字要 ≥ 128。**
⚠️ 脚本自身更保守：**均亮 > 90 就建议深色字 + `bgAlpha 30`**。以它的输出为起点，再按下表微调。

| 图的情况 | 字色 | 图怎么处理 |
| --- | --- | --- |
| 均亮 ≤ 90、亮区零星 | 近白（`#F5F9FF` / `#EAF2FF`） | **什么都不做** —— 原图直出 |
| 亮区成片（脸 / 灯 / 白墙） | 近白 | 只滚降亮部（`-Knee` / `-HiMax`） |
| 均亮 ≥ 130（真亮图） | 取自图色相的深色（`#12172B`） | 抬亮到背景 ≥ 128，或直接用亮图 |

⚠️ **绝不要为了配深字整体提亮暗图** —— 那是把原图洗白。

### 2 定构图（`-CropW` 是主体大小唯一的杠杆）

编辑区比例 **0.917**（实测 443x483，随窗口浮动）。`-CropW` = 取原图多宽的一块：

| `-CropW` | 主体倍率 | 观感 |
| --- | --- | --- |
| 0.72 | 1.39× | 大特写、脸顶到框（❌ 不要） |
| 0.85 | 1.18× | 近景 |
| **1.00** | **1.0×** | **原图大小、完整主体（✅ 默认）** |

`-CropX` 左右取景、`-CropY` 纵向取景（0 = 从顶部）。**上限 1.0**，再大要配 `-CropY`。
运行时 `cover` 只会按编辑区比例再裁一刀，**不可能把主体变小**。

### 3 定色调（只在 V 空间等比缩放）

- 亮部滚降：`V > Knee` 线性压到 `HiMax`。**`Knee` 越高亮部回来越多**（116 → 138），
  `HiMax` 决定压到哪一档（152 → 200，越高压得越轻）。
- **出图默认档：`-Knee 138 -HiMax 200`。** ⚠️ 脚本参数的自身默认是 `255 / 255`（= 完全不动图），
  别照抄脚本默认值出图 —— 那是给"原图本来就合适"准备的。
- 暗部提亮：`-Lift`，**默认 0 = 关**。备用 `-SatBoost`（> 1 额外增饱和，默认 1.0 = 不动）。
- 每通道乘同一个 `V'/V` —— `S = 1 - min/max` 在等比缩放下**不变**，所以压亮部不掉色。

### 4 烘

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\rebake-backdrop.ps1 `
    -Src "D:\...\原图.png" -Dst "D:\...\成品.png" `
    -CropX 0.00 -CropW 1.00 -CropY 0.00 -OutRatio 0.917 -Knee 138 -HiMax 200
```

三步一步不省：按 0.917 裁 → 缩到 2400 宽 + V 空间色调 → **成品尺寸**上 unsharp。
⚠️ 改脚本里的 C# 逻辑要**递增类名**（`X` → `X2`），否则沿用旧编译类型，改了像没改（见 04-workflow）。

### 5 验（两条硬指标）

| 指标 | 期望 |
| --- | --- |
| **亮部 p95** | 成品明显低于原图（金克斯 214 → **177**） |
| **饱和 p95** | 成品 ≈ 原图，**不许掉**（42.2% → **44.1%**） |

⚠️ 对照必须取**同一裁剪区**的原始数据，不是全幅 —— 拿全幅比会得出错误结论。
⚠️ **换图必须重启程序** —— `BackdropService._srcBmp` 缓存了旧位图。

## 三、登记主题（三处一起改）

1. `src\WorkBench\Services\ThemeService.ahk` 的 `Themes` **追加到数组末尾**（`ThemeIndex` 存下标，插中间会顶掉老用户当前的主题）
2. `bg` 与 `bgAlpha` **必须成对**；`bgFit` 可选（不写 = `cover`）
3. 前一条结尾补 `},` —— 漏逗号报 `Unexpected "{"`，窗口再也出不来（方案 A 预检查不出）
