# 05 · 四份资料：意图 / 状态 / 经验 / 对话

## 各管一件事

| 位置 | 唯一职责 | 更新节奏 | 主要读者 |
| --- | --- | --- | --- |
| `docs/INTENT.md` | **去哪**：目标、优先级、红线、非目标 | 方向变了才改 | 人与 AI |
| `docs/STATE.md` | **停在哪**：焦点、已完成、风险、下一步 | **覆盖写入**，会话结束时 | 新会话的第一份 |
| `docs/EXPERIENCE.md` | **怎么走**：验证过的结论、算过账的方向 | 有新结论就加，过时就改或删 | AI 先读，人按需查 |
| `README.md` | 对外解释：是什么、怎么跑、边界在哪 | 定位 / 运行方式 / 重要风险变了才改 | 第一次看到项目的人 |
| `AGENTS.md` | **入口地图**：仓库结构、命令、按改动选读什么 | **≤60 行**，只链接不复述；细则一律进 `.clinerules` | 每个新会话的 AI |
| `<资料根>\conversations\` | 用户原话与可见对话 | **每次会话结束必写一篇**（同会话多轮追加） | 用户本人 |

`README.md` 与 `AGENTS.md` 是**入口**（分别对外 / 对 AI），不算「四份资料」之一。
`AGENTS.md` 由 `check-docs.ps1` 校验：相对链接必须存在、行数 ≤ 60 —— 防止它膨胀成第二份规则。

**当前任务要落盘时**（跨 >1 会话，或预计 >3 个提交的功能）：建 `specs/current/spec.md`，
写「要做什么（含验收）/ 不做什么 / 动哪些模块 / 已知风险」；功能合并后清空或归档。
单轮能收的小事**不建** —— 空目录只会变成负担。

**历史不单独记** —— `git log` 就是历史，提交信息写清「做了什么 + 为什么」。
**对话原文不进 Git** —— 私人目录独立保存。

| 资料 | 放哪 | 进 Git？ |
| --- | --- | --- |
| 意图书 / 状态卡 / 经验包 / README | `<仓库>\docs\`、`<仓库>\README.md` | **进** |
| 规则 | `<仓库>\.clinerules\` | **进** |
| 对话档案（用户原话、导出记录） | `<资料根>\conversations\` | **不进**（仓库外） |

| 个人笔记、截图、录屏 | `<资料根>\notes\`、`<资料根>\shots\` | **不进** |
| 真实文档样本（docx / 课件） | `<资料根>\samples\` | **不进** |

`<资料根>` = `D:\03-PersonalFiles\vibe coding会话\SevenWork\`（仓库外；换机器只改这一处）。
子目录**用到再建**，不预先堆空文件夹。

## 个人数据：一律放仓库外

**仓库只放代码、文档、脱敏的测试样本。** 下面这些**永远不写进仓库**：

- 用户的对话原文 / 任何导出记录；
- 用户的真实笔记、截图、录屏；
- 用户给的原始文档（docx / pptx / pdf / 课件）—— 要验就用副本，放 `%TEMP%` 或 `<资料根>\samples\`；
- 含用户名、盘符、内网路径的清单。

⚠ 一旦提交进 Git 就**删不干净**（历史里还在），所以要在**写文件之前**就判断位置，而不是事后补救。
⚠ 临时调试产物（探针脚本、截图、日志）放 `%TEMP%\SevenWorkDev\`，用完删 —— 既不进仓库，也不污染资料根。

## 每次会话结束：固定动作

不是「想起来才做」，而是**收尾清单**，按顺序过一遍：

1. **`docs\STATE.md`** —— **覆盖写入**：当前焦点 / 已完成（带验证范围）/ 未完成与风险 / 下一步。
   状态有变就改；没变就不动。
2. **`docs\EXPERIENCE.md`** —— 只加**真机验证过**的结论或推翻旧结论；没新结论就**不写**（别制造噪音）。
3. **`docs\INTENT.md`** —— **只在方向变了时**改；AI 的建议不能写成用户的决定。
4. **对话档案** —— **每次会话结束必写**（`<资料根>\conversations\<日期>-<主题>.md`，原话不改写）。
   动笔前先 `Get-ChildItem <资料根>\conversations` 看一眼：本次谈过几个主题、目录里有没有对应文件。
   ⚠ 这一步**没有脚本能替你检查**（文件在仓库外）—— 它是收尾清单里唯一「漏了也没信号」的动作，
     所以别再用「本轮算不算方向性」来判断，直接写。
5. **`tools\check-docs.ps1`** —— 退出码 0 才算收尾完成。

⚠ 这四份**各管一件事**：状态卡记「停在哪」、经验包记「为什么」、意图书记「去哪」、对话记「原话」。
**不要把同一句话抄进三份** —— 抄完就开始互相矛盾。
⚠ 只在自己的回复里说「已更新」不算数：文件真的写了才算。

## 状态卡的硬规则

- **覆盖，不追加**。完成项压成一句或直接删，别让「已做完」清单越堆越长。
- 只写四类：当前焦点 / 已完成（带验证范围）/ 未完成与风险 / 下一步。
- **区分「已实现」「已验证」「建议但未决定」** —— 没验过的绝不能写成已完成。
- 下一步最多几条、有先后；不做长期愿望清单。
- **没有变化就不改**，不要为了「更新过」制造提交。
- Plan 模式下不写文件；结论在回复里交接，切 Act 再落盘。

## 经验包怎么加

- 只加**真机验证过**的结论，或**推翻旧结论**（写成「~~旧说法~~ → 新结论（依据）」）。
- 结论要写清前提：宿主方式 / Windows 版本 / 用了哪个样本。没验过标 **推断**，做一半标 **暂停**。
- 「已经算过账的方向」那张表**只增不删** —— 它是防止重复论证的最低成本手段。
- 「报错原文 → 对策」的检索表在 `03-ahk-v2.md`，不要在这里复述。

## 意图书怎么改

- 只有用户明确改变方向时才改。**AI 不能把自己的建议写成用户的决定**。
- 拿不准的取舍放进「还没定」，定了再挪到正式条款。

## 能写成测试的规则，优先写成测试

经验包记「为什么」，测试记「必须是」。一条规则如果能用断言表达，就别只写在文档里 ——
**文档会被忽略，测试会红。**

- 入口：`tools\run-tests.ps1`（AHK 的 `tests\RunTests.ahk` + 前端的 `web\tests\*.test.mjs`）
- 写用例的规则与反向验证步骤见 [`04-workflow.md`](04-workflow.md)
- 覆盖不到的（建窗口、读配置、真实笔记）仍靠真机手验，**不要为此把整个应用拖进测试**

## 对话档案（仓库外）

落盘位置：`<资料根>\conversations\<日期>-<主题>.md`（`<资料根>` 见上面「存储位置」）。
**永远不进 Git**，也不在 `docs/` 里留副本。

**节奏是每次会话一篇**，不是「有方向性才写」—— 2026-10-24 就是这么断的：
10-23 写了三篇，10-24 全天十几轮一条没写，直到用户自己发现。
判断「这一轮算不算方向性」的成本，比写一篇高得多。

- **原话不改写**：用户消息按原样保存，不替换成「用户希望…」。
- **摘要与原文分开**：从旧日志摘出的段落整段标明「历史摘录 / AI 整理」，不得冒充完整对话。
- **标注完整性**：`完整`（工具导出）、`部分`（可见消息）、`摘要`（仅结论）。
  拿不到的内容留空并注明，**不补造**。
- **优先原文件**：有原生导出就存原文件，不要另造一份正文再维护。

## 改完文档之后

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\check-docs.ps1
```

相对链接存在 / `*.md` 是 LF / `*.ahk` 是 CRLF / README 版本与 `Config.Version` 一致 / 围栏成对。
**退出码 0 才算过**，别只看输出。

⚠ 删掉或搬走文件前先反查引用：
`Select-String -Path README.md,docs\*.md,.clinerules\*.md -Pattern '旧文件名'`
