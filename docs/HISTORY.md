## 2026-10-23　资料结构重构（本轮）

- **改了什么**：`PROJECT-OVERVIEW` / `CHANGELOG` / `DEVLOG` / `CAPABILITIES` / `LAUNCHER-GUIDE` /
  `THEME-IMAGES` / 文档地图 / `archive/` / `devlog/` 全部退出仓库，只留 `docs/EXPERIENCE.md`
  与 `docs/HISTORY.md`；`README` 缩成开发期入口；AI 规则从 7 份合并成 5 份。
- **为什么**：维护 22 份文档、每轮还要同步「当前状态 / 待办 / 已放弃」三区，成本已经超过收益，
  而且**反复出现「文档与代码不是同一代」** —— 上一轮刚宣布同步完成，下一轮就发现状态过期。
  进度类信息本可以直接问 AI / 查代码 / 查 Git，不该手工维护。
- **代价**：仓库里不再有「打开就知道现在做到哪」的快照，需要现场核对；对外分发时缺少现成的
  使用手册（等正式发布再写）。旧文档原件与来源校验值放在仓库外的私人目录，不进 Git。
- **验证**：`tools/check-docs.ps1` 通过；`git log` 保留全部历史。

## 2026-10-23　收敛三批：文档、死代码、数据安全

- **改了什么**：① 文档按「WebView2 + Markdown 直存」纠偏，三份过期计划移入归档；
  ② 删 `EditorService`（608 行）与笔记 `PandocService`（113 行）；③ 数据安全六条 ——
  大小写敏感比较、退出看保存结果、收起看保存结果、标签改名同步路径、转换警告不吞、
  DOCX 编号失败不清 `numPr`。
- **为什么**：审查发现保存链路存在「失败也当成功」的路径（退出 / 收窗都不检查结果），
  以及保存判定用 `=` 导致只改英文大小写会被判成没改。
- **代价**：旧 RTF 笔记彻底没有读回路径（但保存链路自 v2.9 起就不产 RTF，能力在删之前已失效）；
  `Alt+Z` 收起现在可能因「取不到正文」而不收起 —— 故意保守，宁可收不起来也不误删文件。
- **验证**：语法预检 0、真机呼出 / 收起 / 保存并退出通过、日志无新记录。
  ⚠ **保存失败的路径未做自动化实测**（需锁文件 + 真实输入），只做了代码审查。
- **提交**：`9274761`（文档）、`1bc38f2`（死代码）、`3e16099`（安全）、`c463ca4`（日志）。

## 2026-10-23　笔记业务闭环 + 外观模块 + DOCX 编号

- **改了什么**：新增 `NoteSessionService` 统一「当前日期 / 实际路径 / 是否载入」，
  保存改成**返回结果**而不是发事件就算；写入改临时文件替换；前端删掉演示正文兜底。
  外观拆成「主题在平台 Service、调节入口在模块」两层。`Alt+M` 新增 DOCX 标题编号固化。
- **为什么**：原来先改日期再推正文，推失败就是「标题是新的一天、屏幕是旧内容」，
  接着一保存就把旧正文写到新日期上；`FileOpen(path,"w")` 先把原文件截断成 0 字节。
- **代价**：DOCX 编号只对指定样本验证过初版，`lvlOverride`、起始值、罗马数字、样式继承
  都不完整 —— **不要对外承诺「通用保真」**。
- **验证**：探针确认载入真实笔记、未编辑不写盘、切新日期生成题头；同一份 23MB 课件转出
  223 个标题且编号保留、155 张图路径不变、源文件哈希与 mtime 未变。

## 2026-10-22　材质去色与「取消开发身份」

- **改了什么**：整站颜色按明度折成中性灰（193 处），底色落在中灰；玻璃层次只靠光影。
  取消 `dev` 工作树、`dev` 分支与「开发身份」配置分支，只留一条 `main`、一份配置、一处日志。
- **为什么**：材质看着像「一块蓝色亚克力」，根因是色相太多而不是 alpha 太高。双工作树的两条
  分支**指向同一个提交**、源码零差异，却带出两份配置、两处日志和每次的搬运成本。
- **代价**：探针 / 调试脚本读写的就是生产配置（缓解：跑前备份 `_config.ini`）；
  没有「稳定版」兜底，改动直接作用于每天在用的程序（缓解：git 历史完整）。
- **验证**：真机复验面板与笔记窗配色、导航高亮、热键清单；两份 `_config.ini` 当时逐行相同，
  不需要数据迁移。

## 2026-10-21 ~ 10-22　WebView2 迁移

- **改了什么**：编辑区换成 WebView2 + Milkdown，笔记**直接读写 `.md`**；`Alt+S` 面板、
  提示词库搬进 WebView2，并抽出 `WebWindow` 统一窗口生命周期；`Alt+T` 主题切换上收到平台；
  砍掉 11 条 AHK 编辑热键与 `SearchFeature`。
- **为什么**：原生 RichEdit 做不出现代排版，也留不住多窗口观感一致；双份归档（RTF 母版 +
  Markdown 副本）只是维护成本 —— 生产库 36 篇已 1:1 配对、rtf-only = 0。
- **代价**：丢掉 RTF 能表达的字符级格式；内存与启动时间需要重新实测（**至今没测，所以不写数字**）；
  文内搜索下线，改用 Obsidian / VS Code。
- **验证**：往返一致（写出去再读回来不变形）、图片落盘、主题切换保留状态。

## 2026-10-20 ~ 10-21　工作台化

- **改了什么**：模块化落地到 6 个模块（笔记 / 文本 / 文件夹 / 外部程序 / 键位 / 外观）；
  热键上下文改由模块自己声明；`Alt+S` 升级成工作台面板（帮助 + 每模块设置页）；
  `Alt+1/2/3` 文件夹槽位；`Alt+P` 提示词库。
- **为什么**：热键和界面散在组合根里，加一个模块要改五处；面板要能「一处看全、一处改全」。
- **代价**：面板三轮改造（原生控件 → WebView2）才稳定，中间版本出现过控件残留、切页丢失状态。

## 2026-10-18 ~ 10-19　模块化重构

- **改了什么**：拆成 `Kernel / Capabilities / Services / Coordinator / modules` 五层，
  代码收进 `src/`，根目录只留启动器；能力层只收数据、失败返回结构体。
- **为什么**：单文件里混着窗口、热键、磁盘与业务判断，改一处要读全文。
- **代价**：重构期间功能冻结；旧版 30 个 class 必须逐个确认在当前实现里有对应物
  （结论：只在旧版有的 = 0），否则会丢能力。

## 2026-10-16　外部窗口与伴生适配

- **改了什么**：`Alt+C` 呼出终端、`Alt+X` 呼出 DeepSeek 网页；笔记窗口在伙伴窗口出现时
  **仅首次**让位并与其对齐，之后位置归用户。
- **为什么**：并排用时手动摆两次窗口很烦；但每次都自动摆会抢用户已经调好的布局。
- **代价**：第二个伙伴呼出时不会触发重排（已知限制）。

## 2026-09-18 ~ 09-20　起点

- **为什么**：打开笔记软件要 3~5 秒，灵感等不起。
