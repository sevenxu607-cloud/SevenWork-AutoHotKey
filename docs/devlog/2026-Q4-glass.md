### 2026-10-22 22:00　五轮探针定论：WebView2 的客户区透不到桌面，模糊也拿不到

**我说**（原话，上一轮定下的三条）
> （1）transparency probe（2）true-transparent 22px board margin
> （3）frameless window + custom titlebar + WM_NCHITTEST

**意图**
用户要的是「玻璃真的透出后面的东西」，不是网页里画出来的假玻璃。
先花一轮把界限探清楚，再决定第 2、3 条还值不值得做。

**决定 / 过程**
- 写 `src\_probe_transparent.ahk`：一个真的 `Gui` + 真的 `WebView2`，逐级叠 DWM 手法，
  每轮截图比对。五轮结论：

  | 轮 | 手法 | 结果 |
  | --- | --- | --- |
  | ① | `DwmExtendFrameIntoClientArea(-1)` + `SYSTEMBACKDROP(3)` | 看得见后方，但**清晰**、无模糊（Win7 blur-behind 早已移除） |
  | ② | 只 `SYSTEMBACKDROP(3)` | 同上；`DwmSetWindowAttribute` **返回 0 却什么都没做**（静默无效） |
  | ③ | `SetWindowCompositionAttribute(ACRYLIC)` | **整个窗口消失**，连标题栏都没了 |
  | ④ | 关掉所有 backdrop + 拦 `WM_ERASEBKGND` | **窗口完全不可见**（`MainWindowHandle = 0`） |
  | ⑤ | 恢复 `SYSTEMBACKDROP(3)` + 不透明板 | 只剩右下一角，**同组合两种表现** |

- 判定：**第 2 条（22px 真透明边距）不可做。** 它能拿到的只有「22px 一圈清晰穿透」——
  看到的是后方窗口清晰的字，视觉上是「窗口漏了」，不是玻璃。而且③④⑤证明这条路
  在真机上**不稳定**（同一组合时好时坏），生产代码不能建立在它上面。
- **第 1 条到此收工**：v2.13 里写的「客户区无法透到桌面」从推断变成实测，
  并新增两条硬阻断（ACRYLIC 杀子窗口 / 无 backdrop 托底则窗口不可见）。
- 下一步只做**第 3 条**（无边框 + 自绘标题栏）：它治的是「像不像现代应用」，
  与「透」正交，不依赖任何 DWM 手法。

**代价 / 风险**
- 花了五轮探针的时间，换来的是一句「做不到」—— 但这是必须买的：不探就会按第 1 条
  去改 22px 边距、改完才发现边缘那条清晰的字，返工面更大。
- ⚠ 探针里那个「拦 `WM_ERASEBKGND`」的手法**不能进生产**：它会连带压掉窗口自身的绘制，
  ④ 就死在这里。生产代码里别碰它。
- 第 3 条一旦拿掉系统标题栏，**DWM 描边 / 阴影 / 圆角会一起消失**（它们是系统画在非客户区上的，
  v2.13 的「硬限制」也说了「能真模糊的只有系统画的非客户区」）—— 玻璃板会从「浮起来」
  退成「贴在桌面上」。这块必须在动手前先验证。

**待办**
- [ ] 第 3 条前置：探「无边框 + 圆角 + DWM 阴影」能否同时拿到（拿不到就不做，否则是退步）
- [ ] 第 3 条：`WebWindow._Build()` 去标题栏 + 前端自绘标题栏 + 前端发起拖动
- [ ] 结论已进 `CHANGELOG` 与 `.clinerules/03` 的踩坑表

### 2026-10-22 21:10　偏灰：底色从近黑抬到中灰，板从压暗改提亮

**我说**（原话）
> 整体的颜色尽量做到偏灰，而不是偏黑。它的这些光雾和灰色可以很好的联动，但是和黑色对比度太高，
> 就会显得这个光雾和黑色很冲突。所以整体颜色可以偏灰一点，通透一点，像是一些灰色的玻璃一样，
> 好吧？打磨一下质感，偏灰。

**意图**
推断：上一版「无色」达标了，但底色压得太黑 —— 白雾贴在近黑底上像「黑板上贴了一块白」，
两块各自成立、合起来冲突。要的是**灰玻璃**：底是灰的、光是灰里的亮，两者同族。

**决定 / 过程**
- 底色抬两档：`--sw-bg` `#1C1C1C → #2E2E2E`、`--sw-bg-alt` `#161616 → #242424`；
  `ThemeService` 的 `win` / `edBg` / `dim` 同步改（标题栏染色与窗口底刷跟着走）。
- **板层从压暗改成提亮**：`rgba(27,27,27,.10~.16)` → `rgba(255,255,255,.03~.09)`。
  灰玻璃是「比背景亮的一层 + 1px 亮棱」，压暗只会读成「更黑的块」。
- 正文层改纯黑轻压 `rgba(0,0,0,.05)` 保对比；深色 inset 阴影整体减淡 15~25%（灰底上像「坑」）。
- 光雾提亮收小：渐变 `0.58/0.2/0.08@54%` → `0.8/0.3/0.08@54%`；五团 54/46/44/40/26 →
  46/40/38/34/28vmin；顶部那团压进板内（`left 42→44%`、`opacity 0.7→0.9`）—— 板里得有一块
  明确的光，否则仍是「均匀灰板」。
- 对比度先算再改：`#2E2E2E` 上正文 `#F2F2F2` = **12.1:1**、`dim #BABABA` = **7.0:1**；
  板提亮到 ≈`#3A3A3A` 后正文仍 **10.1:1**，全部远超 4.5。
- 真机 820×620 + 全屏两轮截图：灰玻璃 / 光成形 / 板外留边可见；面板 `Alt+S` 同步变灰、
  `v2.13` 与 24 条热键清单正常；全程 stderr / `_error.log` 为空。

**代价 / 风险**
- 与「纯米黄」那套的历史数值彻底脱钩，回退要连 `ThemeService` 一起改。
- 灰底上白雾更难读，只能靠「提亮 + 收小 + 陡衰减」补；换更亮的显示器可能又偏淡。
- 客户区**仍然透不到桌面**（WebView2 独立合成表面），「通透」是画出来的。

**待办**
- [ ] 观感验收 → 提交 + ff `main`

### 2026-10-22 01:30　「琉璃 · 极光霜」定调：先做材质样板（S0）　[追溯整理]

**意图**
诊断下来病根不是配色：原生 AHK 窗只有 `Gui.BackColor` + `LVM_*` 整数上色，没有材质能力；
Web 层的 `backdrop-filter` 背后是纯色，**无可透之物** —— 模糊纯色仍然是纯色。
所以先把「材质」单独立起来，用一个样板页验收，再决定怎么推广。

**决定 / 过程**
- 定了「材质六层」验收框架：①光雾 ②霜 ③玻璃面 ④厚度 ⑤冰棱 ⑥specular。
  现状体检：①②④⑤⑥ 几乎为 0，仅 ①③ 各有一点点 —— 这就是「像个深色主题」的全部原因。
- **「透桌面」不是必需，「内部有光雾可透」才是必需**。Web 层铺满窗口 + 自绘光雾能拿到
  绝大部分观感，不必先攻克 WebView2 透明 + 系统亚克力的深坑。
- 样板落在 `web/src/theme/lab.css` + `components/GlassLab.vue`，作用域只有 `.lab`，
  刻意不碰 `html[data-style='glass']` —— 笔记窗现有观感一个字不动。`?view=lab` 进入。
- 页面自带三档预设 + 六个滑杆（模糊 / 饱和 / 白层 / 霜 / 冰棱 / 反光），
  调完把右下角 JSON 抄走即为定型参数。

  平均成暗青）、玻璃必须带 scrim（否则亮光团上方的浅色字全糊）、噪点要 `rect opacity` 且
  `soft-light`（`overlay` 会提亮成乳白塑料）、光团中心不能全落在视口外。
