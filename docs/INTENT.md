# 意图书

> 这份文件只回答**去哪**：要做成什么、冲突时先保什么、哪些明确不做。
> 它**很少改** —— 只有方向真的变了才动。当前停在哪见 [`STATE.md`](STATE.md)，
> 踩过的坑见 [`EXPERIENCE.md`](EXPERIENCE.md)。
>
> 来源：项目过程里出现过明确原话的地方标「原话」，其余是从既有文档与选择中归纳的。
> 归纳不等于你的签字确认 —— 觉得哪条不对，直接改。

---

## 为谁做

- 首先服务**你一个人的 Windows 工作流**，不预设大众产品需求。
  项目最初的定位是「本地速记工具，为 Obsidian 收件箱场景设计」；后来范围放宽成
  **个人工作台**，速记退成其中一个模块 —— 这个转变是有意的，不是失控。
- **单人维护，所以「以后每次改要动几处」是硬指标**。任何设计都要算这笔账，
  算不过来就换简单做法。

## 解决什么

- **少切换**：记一笔、存个提示词、开终端、转个文档，都不该先找窗口、找软件。
- **不锁死**：记下来的东西必须落地成普通文件，任何编辑器都能打开。
- **不打断**：呼出快、保存无感、退出不啰嗦。

## 优先级（冲突时按这个顺序）

1. **数据安全** —— 宁可少一个功能，也不能把已经写下的东西弄坏。
2. **日常可靠** —— 每天走的那条路径必须稳；边缘功能可以等。
3. **低打扰** —— 不弹窗、不抢焦点、不要求多余确认。
4. **外观体验** —— 好不好看是目标之一（原话：「透明不是我的目的，美丽惊艳的前端才是目的」），
   但排在可靠之后。
5. **维护成本** —— 同等效果取简单方案；复杂的必须能说清换来什么。

## 非目标（明确不做）

| 不做 | 理由 |
| --- | --- |
| 通用笔记软件（搜索 / 双链 / 图谱 / 同步） | 交给 Obsidian、VS Code；本项目只负责「快到不用想」 |
| 通用格式转换器 | `Alt+M` 只解决「手上有个 docx / pptx 要进库」 |
| 跨平台 | AHK v2 + WebView2 的边界就是 Windows |
| 堆配置项 | 全局参数只留真正影响观感的那几个 |
| 背景图主题 | WebView2 客户区是独立合成表面，AHK 侧贴图（`Static` + `SS_BITMAP`）整片被它盖住 —— 配了也看不见。要装饰就改 `glass.css` 的材质层 |
| 为架构好看而抽象 | 分层是为了能删模块，不是为了画图 |

## 红线

- **不静默丢数据**：保存失败必须让用户看见；**宁可拒绝操作，也不假装成功**。
- **不动 Kernel**：需要改它时先写清为什么，别顺手改。
- **跨模块不直接调用**：只能走 `EventBus` 或各自的热键。
- **不引新框架**：前端就 Vue + Milkdown，后端就 AHK + WebView2。
- **承诺要有证据**：没实测的数字、跨环境的结论、「保证不丢」这类话，不写进文档。

## 本阶段的方向（2026-10-23 定）

- **管理面板是正常窗口**：可以最小化到任务栏；`×` / `Esc` 只是隐藏，不退出程序。
- **退出统一走 `Alt+Shift+S`**（旧 `Alt+Shift+Z` 撤销，不留别名）：退出前逐条问
  笔记是否存住、提示词有没有没保存的修改、面板里有没有没提交的设置 ——
  任何一条不过就**不退出**，并把原因写出来。
- **外观只做主题选择**：撤掉材质浓度 / 圆角 / 动效 / 密度四项滑杆 ——
  单看几乎看不出差别，不该让用户凑参数。观感由每套主题给全；参数试验留在开发工具。
- **笔记体验按旧版习惯补齐**：状态栏信息、保存反馈、字体与排版都以「用起来一样」为准，
  不能拿「参数已经传到前端」当验收。
- **格式转换要可靠、可解释，不承诺保真**：表格 / 编号 / 图片优先保住内容与结构；
  Markdown 表达不了的视觉细节明确降级，不能静默丢失。

## 2026-10-24：七个核心应用 + 三区域

- **模块统一成七个核心应用**：笔记、文本、文件、应用、视界、按键、主题。
  `Id` / 目录 / 事件名不动，只统一显示名与面板文案。
- **窗口只认三块固定区域**：记录区（笔记）、辅助区（终端 / 浏览器 / 浮层）、
  工作区（其余）。几何由平台 `ZoneService` 持有，`VisionModule` 只是用户入口。
- **取消「笔记适配伙伴窗口」**：`Launcher.Preparing/Opened/Failed`、`PeerCoordinator`、
  `PeerLayoutService` 全部删除；笔记原生呼出就在记录区，不再跟着别的窗口移动。
- **槽位机制统一**：文件 `Alt+1/2/3` 与应用 `Alt+Shift+1/2/3` 都是「目标 + 区域」。
- **一键启动 / 自定义布局暂缓**：先只做 `Alt+Shift+V`（把已开窗口摆回区域）；
  没有执行入口之前不写入布局字段。

以上是**已确认的方向**，不是建议。原话见同目录外的对话档案（2026-10-23 / 10-24）。

## 2026-10-25：先做 portable 编译分发

- **决策**：先做无需安装 AutoHotkey 的 portable 编译版（exe + `web\dist` +
  `WebView2Loader.dll`），暂不把安装器 / 签名 / 自动更新作为第一版门槛。
- **Pandoc 降级**：文档转换只服务 `Alt+M`，改为可选 sidecar；正式包不打包
  `pandoc.exe`，缺失时该功能明确不可用。
- **外部应用**：Obsidian / Everything / PyCharm / VS Code 等继续只作为应用槽位的
  用户配置，不参与编译和发布包。
- **WebView2** 是硬运行时依赖；loader 随包，runtime 由 Windows/安装引导提供。
- **验收门槛**：干净机器（无 AHK / Node / Pandoc）能解压启动，`Alt+S` 面板可用，
  退出正常，用户 Vault 不被安装 / 卸载破坏。

## 还没定

- 安装器（Inno Setup / MSIX）、代码签名、自动更新的具体节奏 —— portable 版稳定后再做。
- 区域尺寸（辅助区宽高 / 间距）是否要暴露到面板；第一版写死在 `[Vision]`。
- 一键启动的启动清单与异步模型（串行会占住热键线程）。
- 同区多窗口是否要做堆叠（现在只保证落区，不保证互不重叠）。
