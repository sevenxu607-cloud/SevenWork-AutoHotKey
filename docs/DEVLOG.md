## 已放弃 / 已回退的方案（别重复踩）

| 方案 | 放弃原因 |
| --- | --- |
| 无条件 `EM_SETSCROLLPOS` 写回 | 用户正拖滚动条时被弹回，表现就是「滑条经常无法滑动」 |
| `EM_SETEVENTMASK` + `EN_CHANGE` 通知 | 本机 `RichEdit50W` 上掩码设不上：读回恒为 `0x0`，`WM_COMMAND` 一次都不来 |
| 50ms `SetTimer` 轮询 + 脱节守卫（`ScrollSyncFeature`） | 真机报错；我这边探针全绿、无法复现。备份在 `%TEMP%\SevenNoteDev2\reverted_20261018_113204\` |
| 保留 v2.4.3 单文件快照作对照（`docs/legacy/`） | 重构已验证成功：旧版 30 个 `class` 全在当前 57 个里（只在旧版有的 = **0**），6 个顶层函数已转为类方法；文件可从 `git checkout a115ea3 -- docs/legacy` 取回。留着的坏处是「打包纯代码给 AI」时会误纳 4209 行，并让助手把两套架构混起来 |
| RTF 双格式存档（`.rtf` 母版 + `.md` 副本） | 生产库 36 篇 `.rtf` / `.md` **已 1:1 全配对、rtf-only = 0** —— 双写只是维护成本。Markdown 升为母版后，Pandoc 退回「导出」一角（`Alt+M`） |
| AHK 侧 11 条编辑热键（撤销 / 重做 / 删行 / 复制行 / 上下移行 / 搜索 / 回车 / 退出等） | 编辑器自带 + Obsidian 能做的都不重复实现；`Ctrl+Y` 让出来正好给原生重做。`Ctrl+T` 时间戳不可替代，保留 |
| 主题表挂 5 套（护眼绿 / 纸白 / **星空** / **金克斯**） | **暂缓，非放弃**：两套图主题的前端消费（`bg` / `bgAlpha` / `bgFit`）还没打磨完，切过去只有一块纯底色。4 条定义见 git 历史（`b707a0f` 之前），接回时往 `Themes` **末尾**追加即可 |
| 双工作树 + `dev` 分支 + `_dev.flag` 身份（v2.14 删） | 两条分支**指向同一个提交**，源码零差异 —— 那条分支不承载信息，却带出两个目录、两份配置、两处日志、每次「dev 提交 → ff 到 main」的搬运。隔离收益（探针不碰生产配置）远小于管理成本。代价改成「跑探针前先备份 `_config.ini`」 |
| WebView2 客户区「真透明 + 真模糊」（v2.13 定论） | 五轮探针：Win11 的 backdrop 只作用于系统画的非客户区；`SetWindowCompositionAttribute(ACRYLIC)` 会把 Chromium 子窗口裁掉（整窗消失）；拦 `WM_ERASEBKGND` 又必须有 backdrop 托底，否则窗口不可见，且同组合时好时坏。上限是「22px 一圈清晰穿透」= 看到后方清楚的文字，像 bug 不像玻璃 |

### 2026-10-23 16:05　DOCX 转 Markdown 保住标题编号

**我说**（原话）
> pandoc在文本模块中用于转换选中文本为markdown形式,但是目前的转换不够完好,可以继续优化?保留可视化一致的格式转化?现在会转换后丢标题号?
> （补充）`...NLP1.1.1.docx` / `...NLP1.1.1.md`；不需要片段转换,多文件一键转换

**意图**
资源管理器多选文件一键转（`Alt+M`），要求转换后**标题编号还在**、观感与原文接近。

**决定 / 过程**
- 只读核了那份 23MB 课件：编号来自「样式 → numPr → numbering.xml」的模板
  （`第 %1 章` / `%1.%2` / `%5）` / `（%6）`），正文里没有这些字 —— pandoc 只取文字，
  于是 223 个标题层级都在、编号全丢。**先定病因再改代码。**
- 新增能力 `DocxNumberFix`：按原模板逐级算编号写进标题文字，段落 `numPr` 改 `numId=0`；
  再由 `StripStyleNumbering` 删掉标题样式上的 `numPr`。
- 顺序固定为「固化编号 → 删样式编号 → 改样式名」：判标题要靠样式名，
  一旦先改成 `heading 5`，`LevelOf()` 就认不出「半括号标题（五级）」了。
- `numId=0`（Word 的手动取消编号）**不补号、不推进计数** —— 样本里「完整案例如下：」正是这种，
  补了号 223 → 224 还会挤乱后面的二级编号。
- 编号是增强：任何一步失败都退回原件照常转，`warnings` 走日志与 ToolTip，不谎报「完全还原」。

**代价 / 风险**
- 三步里我踩了两个坑，都已修并写进 `CAPABILITIES.md` 4.7：
  ① 只固化编号、不清 numPr → pandoc 仍当有序列表，整篇「1. NLP导论」，零标题；
  ② 段落切片用**改后**的 para 长度推进 `last` → docx 结构损坏，pandoc 只给
  `couldn't parse docx file: DocxError`。
- 还有一次 `no-styles` 查了整轮：`_FixNumbers(..., &warnings)` 的 ByRef 传数组报
  `requires a variable reference`，异常被外层 `try` 吞成一句 reason。已去掉 `&`、并让
  `no-styles` 带 `detail`。
- 实测（同一份课件，临时目录内转换）：223 个标题、`# 第 1 章 NLP导论` / `## 1.1 定义` /
  `### 1.2.1 文本分类` / `##### 1）安装pytorch` / `###### **（1）精确模式（默认）**`；
  `完整案例如下：` 保持无编号；155 张图、相对路径 `sample_media/media/image1.png` 不变。
  源 docx 与旧 md 的哈希、mtime 全程未变。
- 已知边界：`lvlOverride`（单实例改起始值）未处理；罗马数字等格式按十进制并告警；
  字体/字号/分页/复杂表格仍不进 Markdown。

**决定 / 过程**
- 新增 `NoteSessionService`（模块 Service）：当前日期 / 实际路径 / 是否已载入 + `Open()` / `Save()`。

- `_Read` 区分三种情况：没文件（给题头）/ 有文件读不出（**失败**）/ 读到。原来读失败静默回退成
