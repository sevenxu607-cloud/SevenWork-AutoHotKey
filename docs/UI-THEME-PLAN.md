# 前端主题改造计划（跨模型执行清单）

> 口径：v2.14 / 2026-10-23
> 本文件是交给编码助手的**执行规格**，不是概念说明。产品方向已定，执行时不要重新讨论或要求用户逐项选参数。

---

## 一、需求与已定决策

用户原话：

> 透明不是我的目的，美丽惊艳的前端才是目的。但是，我想实现的第一个主题就是这种，嗯玻璃板一样的这种效果，可以往这个方向上靠吧。然后后续可能还会出，开发出新的主题，就是切换，一键切换前端的主题。然后，但是我觉得应该给你自由发挥的空间，让你展示一下你理解的美观和惊艳吧，现代的前端炫技一样的效果。

**已定**

1. 保留 **AHK + Vue + WebView2 + Milkdown**，不换宿主。
2. 第一套主题方向：中性灰、悬浮玻璃板、空间光场、细腻交互（设计代号「琉光」）。
3. **不要求透出真实桌面**，背景／玻璃／光照全部在网页内部完成。
4. 第一套不得是「深色卡片 + 圆角」，也不得是整窗白雾；必须有板面、厚度、边缘、前后空间。
5. 先做工作台面板（`Alt+S`），再推广到提示词库、笔记窗。
6. 保留多主题能力，但本轮只交付**一套正式主题**。

**禁止**

- 继续 DWM 真透明实验；加 `WS_EX_LAYERED`；拦背景绘制；改系统透明设置。
- 换 C#／WinUI／Electron 等宿主。
- 引入新的 UI／动画／测试框架。
- 擅自提交、清空工作树、归档开发日志。

## 二、视觉规格

### 构图

保留双板布局（左导航 200–216px / 右内容），**板间与四周必须留背景空间**。主验收尺寸 940×700 逻辑像素，不靠放大窗口掩盖排版问题。

| 项 | 范围 |
|---|---|
| 外围留边 / 板间距 | 14–20px |
| 主板圆角 | 14–18px |
| 控件圆角 | 8–12px |
| 正文 / 页标题 | 13–14px / 20–22px |

数值是起点，不是机械套值。

### 材质分层（由后向前）

1. 稳定底色（深灰，非纯黑）
2. 空间光场（少量、非均匀、有位置关系）
3. 玻璃板（半透明填充 + 背景模糊）
4. 板边与厚度（亮边 / 暗边 / 接触阴影）
5. 局部反射（指针经过时的克制高光）
6. 内容（不得随背景光照忽明忽暗）

**硬要求**：板后必须有明暗结构，否则模糊后仍是一块灰；不铺乳白；光场不平均填满；不用高饱和霓虹、持续闪烁、强三维倾斜；玻璃感靠边缘与光线，不靠无限加大 `blur`。

### 动效预算

| 动作 | 时长 |
|---|---|
| 悬停 / 按压 | 100–160ms |
| 切页 | 160–240ms |
| 呼出 | 360–480ms |
| 主题切换 | 240–320ms |

连续操作覆盖上一次动画、不排队；切页不重建编辑器、不丢焦点；减少动效时取消装饰运动但保留清晰状态；粒子只在呼出等少数时机短暂出现。

**本轮不新增「日用档 / 展示档」设置面板。**

## 四、主题切换契约

保留：`ThemeService` 作为运行时主题事实源、`Theme.Changed` 广播、`applyTheme()`、`style`、`material`。不立即重构成插件系统，不改下标兼容方式。

必须补齐：

1. 记录本次 `material` 写入的变量，下一主题前移除这些**旧覆盖**。
2. **不要清空整个 `documentElement.style`**（会误删编辑器字体等非主题状态）。
3. 材质键采用真实白名单（现有正则只限格式）。
4. 快速连续切换时，旧过场回调不得清理新过场状态。
5. 首次应用不播「换主题过场」，后续切换才播。
6. 不因切主题重建页面 / WebView2 / Milkdown。
7. 同一主题重复应用幂等。
8. 背景装饰与粒子受当前主题约束。

主题选择 UI 放在首套视觉完成之后；只有一套时不展示假选项。

## 五、显示与动画契约

**不能**只把 `700ms` 换成 `NavigationCompleted` 就宣布完成。

就绪条件至少区分：主题已应用（或已回退）、当前视图首屏初始化完成（或已显示错误态）、窗口确实可见且未最小化。

保留公开接口：`window.__sevenwork.applyTheme`、`window.__swfx.reveal/reset/stats`。

要求：

- 宿主显示后请求入场；未就绪则等待，不丢掉这次请求。
- 用有截止时间的重试或明确就绪通知，不无限轮询。
- 定时器闭包存字段，关闭时取消；用序号排除过期回调。
- 关闭时先取消待入场、复位效果，再隐藏。
- 迟到回调不得重新显示窗口。
- 页面初始化失败要显示错误或回退，不能永久透明。
- 不靠「默认隐藏正文」赌动画一定被调用。
- 所有 WebHost 调用显式传 `hwnd`。

已知坑：

- `WebWindow.IsOpen()` 实际判断「窗口是否存在」，**不是是否可见**，不能作为异步显示的唯守卫，也不要顺手改它的公共语义。
- `WindowFeature.Hide()` 里有不带 `hwnd` 的 `Eval`，接入时改为显式目标。

## 七、验证清单

- 构建：在 `web/` 跑 `npm run build`，检查真实退出码。**Vite 构建 ≠ Vue 类型检查**，不得声称跑了未安装的 `vue-tsc` 或自动化浏览器测试。
- AHK：用 `D:\02-Apps\AutoHotkey\v2\AutoHotkey64.exe` 跑根启动器 `SevenWork.ahk`，不能只做注入 `ExitApp()` 预检；记录**新增**日志，不靠清空历史错误制造「无错误」。
- 文档：`tools\check-docs.ps1` 退出码必须为 `0`。
- 场景：首开 / 再开 / 快速开关 ≥10 次 / 切页与键盘导航 / 输入与浏览目录 / 保存成功与失败 / 多窗口并存 / 临时 A→B→A / 减少动效 / 长内容滚动 / 笔记编辑内容不变 / 当前 DPI 无遮挡（其他 DPI 未测须标注）。
- **不得**用同脚本 `Send` 证明上下文热键通过。
- 证据：面板「全部热键」、「文件夹设置」、提示词库、笔记窗截图，加入场与切页关键帧或录屏；存时间戳临时目录，含个人桌面内容的截图不进仓库。

## 八、完成定义

同时满足才算完成：

- 第一套主题有明确玻璃板观感，静态与动态均有实质变化。
- 未借换宿主或真透明实验偏离目标。
- 主题切换无残留，未来主题有明确接入位置。
- 首帧不依赖固定 `700ms`。
- 现有功能、输入状态、多窗口行为未破坏。
- 构建、真机、文档检查均有实际结果。
- 最终 diff 无临时主题、实验色、无用探针。
- 输出绝对路径改动清单、验证结果、截图位置、剩余限制。
- **不把「已改代码」当成「视觉已验收」。**
